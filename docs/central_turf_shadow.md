# 中央草地影子预测

> 历史版本说明：此页记录 `86cff3a` 的影子部署。后续已按用户要求切换为[中央草地正式模型](central_turf_active.md)，正常任务不再运行影子模型，旧环境变量不再控制正式草地预测。以下运行与关闭说明仅适用于旧版本；已有影子记录和模型文件保留不改。

## 用户结果保持不变

本次启用的是中央草地影子预测，不是替换正式预测。旧模型仍决定页面前五、印记、信心和马券；新模型只在正式预测已经生成并保存之后读取独立副本，额外计算排序并写入审计包。影子结果不会传给LLM解释、投注或用户自定义预测。

仅中央草地且使用兼容的`accuracy_default`评分配置时计算。地方、中央泥地不调用影子模型；自定义评分、市场特征启用或不兼容配置记录为跳过。影子模型加载、校验、计算失败只记录失败状态，不能接管或改写正式预测。

模型：`central_turf_history_shadow_v1_20261025`，特征协议：`central_turf_history_direct_v1`。

版本文件位于`keiba_llm_agent/models/turf_shadow/`，与现有正式模型目录分开。训练使用截至2026-10-25的全部630场合格中央草地full、8,324个出走观察，沿用已验证历史表现候选的超参数和等出走马训练权重。292维包括现有28维分项、204维连续历史及相对特征、60维补充历史表现表达。没有使用赔率、人气、马匹身份或目标赛马体重。

本次全量拟合只是生成影子发布模型，不是新的准确率验证。此前折外与时间回测见[补录验证报告](turf_supplement_validation_20261025_zh.md)。历史补充字段是事后取得的，不能把该模型回放训练期比赛称为真实前向验证。

本次发布校验：630场、8,324个出走观察的运行特征与冻结回测特征逐值一致；经过旧模型正式重排后，新增特征仍一致；模型保存再加载的输出一致，官方预测和输入对象均未改变。本机单场影子计算平均约38毫秒，不含原有抓取和LLM耗时。模型SHA256为`81c5e44ef12e1abfe1f5bf495bcbb91449604c3d5f23a72f5003f95a7adcb652`。

相关回归共281项，其中279项通过、2项因已有HTML样例缺失跳过。覆盖影子失败隔离、关闭、其他范围不调用、市场和目标体重隔离、模型校验、赛前资格、早期/最终回传、重复版本、结算保留及清理保留；需要原子替换的临时目录测试在授权环境通过。这不等于已观测到远端首场影子任务成功，部署后的实际留档仍应检查。

## 默认运行与关闭

`KEIBA_CENTRAL_TURF_SHADOW_MODE`只支持：

| 值 | 行为 |
|---|---|
| `shadow`，默认 | 计算并留档，不改正式预测 |
| `off` | 不加载影子模型，中央草地审计记录关闭状态 |

不支持`active`或任何替换正式排名的模式；非法值记录失败，正式预测继续。

当前远程预测在GitHub Actions的`agent-prediction-remote.yml`执行。工作流会读取仓库变量`KEIBA_CENTRAL_TURF_SHADOW_MODE`，未设置时为`shadow`；需要关闭时，将该GitHub仓库变量设为`off`，作用于后续任务。仅在Render设置同名环境变量不能控制另一个GitHub运行进程。直接在本机或Render运行Agent命令时，设置实际运行进程的环境变量。

不需要重新开启原有总重排开关，不需要覆盖`central_turf_place_v1.joblib`，也不需要更改地方和泥地配置。将来正式替换排序需要单独实施和验证，本模块没有自动晋级逻辑。

## 审计留档

每次预测生成的本地完整审计包在：

```text
keiba_llm_agent/data/backtest_audit/{race_id}.json.gz
```

影子记录位于：

```text
shadow_predictions.central_turf_history
```

成功记录包含：

- `authoritative=false`、状态、模型版本、模型SHA、特征协议和源码哈希。
- 正式模型完整排序和前五、印记、生成影子结果时所对应的正式预测摘要哈希。
- 候选完整排序和前五、各马分类器信号。信号未校准，不展示为真实前三概率。
- 马号顺序、292维特征矩阵、缺失值数量、特征哈希、去市场信息后的输入哈希。
- 历史抓取状态计数、生成时间、耗时、训练截止、计划开跑时间及前向资格说明。

缺失特征使用JSON的`null`记录；抓取失败与原本无历史通过状态区分。失败、跳过和关闭也留状态，不能只统计成功样本而隐藏采集问题。

现有GitHub回传会把完整gzip审计包上传Render；服务端按阶段和任务版本保存：

```text
pipeline/data/agent_backtest_audit/_versions/{race_id}/{early|final}/{version_id}.json.gz
```

实际存储根目录仍遵循现有环境配置。正式预测继续保存在`agent_predictions`，不会附带影子字段供前端消费。结算只补入`outcomes.result`，不会改影子排序。重复回调不覆盖已经存在的版本文件。清理任务对含影子记录的早期审计及对应预测整体保留，不因最终版本完成而删除；本次没有运行任何真实数据清理。

## 后续如何判断效果

使用下载后的完整Render快照，只读统计所有合格影子记录：

```powershell
python -X utf8 pipeline/report_turf_shadow.py --snapshot analysis_outputs/<最新快照目录> --output analysis_outputs/<新报告名>.json
```

统计规则：

1. 每场采用现有规则选出的一个有效审计版本，不把早期和最终重复计作两场，不因某版本表现好而选择它。
2. 只比较同一模型版本与哈希、已结算full记录中的新旧排序；两个方案使用相同比赛和实际前三。
3. 比赛日期须晚于训练截止；影子生成时间、Render接收时间必须都有时区且严格早于计划开跑时间。缺时点证明、晚到或训练期回放单列排除，不混入前向表现。
4. 统计覆盖席位数、席位召回率、三匹全部覆盖和至少覆盖两匹。样本为空时准确率显示未知，不报告为0%。
5. 全部合格样本用于判断，不以最近七天单独挑参数。早期/最终阶段、头数及采集状态可以另作分层，但不能用事后表现拼接最优版本。

命令也列出缺影子记录、失败、未结算和时间不合格的数量。计划开跑时间仍不等于实际开跑时间；没有赛前时间证明的记录不能因为有模型输出就视为合格。

## 训练复现与安全边界

```powershell
python -X utf8 pipeline/train_turf_shadow.py --prepared analysis_outputs/turf_place_followup_20261025_v1/prepared.joblib --supplements analysis_outputs/turf_enrichment_20261025_v1 --output analysis_outputs/<新的发布校验目录>
```

脚本只写新的`analysis_outputs`子目录，不覆盖既有数据或线上模型。它逐场校验冻结来源哈希、回测特征与运行特征一致性、正式模型重排后的特征一致性，以及模型保存再加载后的预测一致性。模型文件和元数据应在校验通过后成对发布；变更训练数据或特征时应使用新的模型版本，不能覆盖同版本后混合统计。

运行时校验模型哈希、特征顺序、源码协议和scikit-learn版本。正式评分源码变化后若协议不匹配，影子模型记录失败而不是静默运行。源码哈希统一换行符，以兼容Windows和Linux检出。

现有正式评分、系数和模型文件不变。原始预测、赛果、审计及本地下载快照保留；只提交源码、测试、说明和新增的小型影子模型文件，不提交下载数据或实验缓存。
