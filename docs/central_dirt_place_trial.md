# 中央泥地前三覆盖试用

## 改动与边界

- 目标：选出的五匹马覆盖更多实际前三席位，不以冠军命中率替代。
- 只改变中央泥地、赛前有效输入名单至少 13 匹的 Agent 排序。中央草地、地方、障碍及不足 13 匹的中央泥地保持原算法。
- 模型使用全部中央泥地已结算 `full` 训练，而不是只训练大头数或最近一周。
- 实际前三均标记为 1，其余为 0；每匹马同等训练权重，不再给冠军或正类额外权重。全局常数权重只保持原正则化尺度。
- 65 个特征：原分项与场地特征 28 项，加上近走、头数、距离、休赛、枠番、负重及缺失标记等 37 项；赔率、人气不参与。
- 大头数直接按前三模型输出排序，不混合原冠军模型，不锁定原第一名。
- 分项分数及原总分明细不变。最终展示排序使用重排分数，但它不是百分比概率；模型输出也未经过独立概率校准。
- 新模型独立保存，不覆盖中央草地、地方或任何历史预测、赛果、审计数据。

环境变量 `KEIBA_CENTRAL_DIRT_PLACE_MODE`：

| 值 | 行为 |
|---|---|
| `active`，默认 | 大头数采用新排序，同时记录旧排序 |
| `shadow` | 使用旧排序，另存新候选排序和模型输出 |
| `off` | 完全关闭中央泥地新模型，回到旧排序 |

未知配置值按关闭处理。原总开关 `KEIBA_SCOPE_RERANKER_ENABLED=0` 仍优先关闭所有重排。只回退泥地时不要关闭这个总开关。环境变量须配置在实际执行 Agent 预测的服务或作业中，并重启对应进程。

模型缺失、校验不符、名单不匹配、特征维度错误或输出无效，均回退旧排序并记录原因。回退只影响之后的预测，不改写已经保存的预测。

`scope_reranker_config` 记录版本、模式、头数门槛、训练目标；`scope_reranker_result` 记录原排序、实际使用排序、候选排序及候选模型输出。现有完整审计包会原样保存这些字段，不另建或清理原始数据目录。

My 预测接口仅消费原始分项与调权系数，不使用最终排序分数；本次不修改该接口、用户参数或界面文案。

本地核验：3242 场 My 输入逐项一致；462 场草地、2399 场地方、27 场其他与 112 场小头数泥地排序不变；354 场泥地的 65 维特征与训练输入完全相同；242 场大头数的完整预测、标记和审计往返一致；1770 次实际运行路径的折外排序与回测一致。17594 个下载原始文件在核验前后校验值不变。


验证脚本只输出到新分析目录，不自动覆盖生产模型。生产一致性核验要求当前安装的模型对应同一次验证；后续新训练模型必须先在临时模型目录核验，再显式更新版本与模型文件，不能把原训练集重放分数当作折外效果。

这里的对照是本次修改前的泥地评分算法。此前通用实验脚本的泥地扫描基线也仍是无重排版本；今后评估下一版候选，必须把本次模型纳入同折对照，不能把对旧算法的提升冒充对当前已部署版本的提升。
