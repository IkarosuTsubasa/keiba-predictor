# 训练评级正式前向测试

本次补上此前采集功能缺少的预测和赛后评估环节。中央草地正常生成正式预测后，另用已回测的训练评级候选生成影子排名，两份结果一起保存到完整审计包。网站继续显示现行正式模型的排名。

## 固定测试方案

- 基线：`central_turf_class_context_v1_20261025`，316 个特征。
- 候选：`central_turf_workout_shadow_v1_20261026`，相同基线特征加 8 个训练特征，共 324 个；使用此前验证过的参数，不在这一步重新挑参数。
- 新增特征：当前训练评级、先前已知评级、评级变化、距先前评级天数，以及各项在同场中的相对值。
- 先前评级取随模型冻结的训练样本历史库，截止 2026-10-25；不会在不同云端执行器上自行更新成不同版本。未来新抓资料另外完整保存，更新历史库必须另发可追踪版本。
- 本轮只测试量化评级，短评保留作原始资料，不进入模型；赔率、人气均不进入特征。中央泥地、地方没有完成此候选对应的验证，不套用草地模型。

历史训练源仍是同一连续分析中已经下载并校验的 Render 快照和 630 场合格完整审计，8,324 匹次，2026-05-16 至 10-25。新模型按这批已验证样本全量训练，仅为后续实际比赛推理服务；全量训练成绩不作为新增准确率证据。既有证据仍为 630 场重复分折和 522 场时间验证；此处不新增旧分数调权、泥地或地方回测结果。

## 纳入条件

必须是训练截止日期之后的中央草地比赛，现行正式模型正常启用，出马表与训练页的比赛编号、马番、马匹 ID 对应，原始页面校验一致且至少有一条有效评级。

当前资料接收、新模型推理、正式预测传回服务器均须早于开赛，时间须含时区。缺开赛时间、资料抓取失败、模型校验失败、赛后补抓或晚到预测都记录原因，不混入真实赛前命中率。部分评级缺失保持缺失，不当作差评。

## 保存和结算

完整审计的 `shadow_predictions.public_workout` 保存两套排名、模型与特征校验值、324 列输入、训练资料接收时间和分组信息。它不会改动正式预测、投注建议、LLM 输入或前端文案。

现有赛果回填流程自动生成 `outcomes.public_workout_comparison`，记录两套前五各覆盖几个实际前三席位、是否三匹全中、是否至少两匹，以及冠军前三/前五与冠军名次。尚无赛果只算待结算。

使用以下命令读取已下载快照汇总；报告只写入独立分析目录，不修改原始记录：

```powershell
python pipeline/report_public_workout_shadow.py --snapshot <快照目录> --output analysis_outputs/<新报告名>.json
```

每场只选一个有效审计版本，避免早期、最终和重试版本重复计数；分组分别报告无有效近走、有近走、重赏、13 头以上、16 头以上。不同模型校验值不能混在一起统计。没有实际新比赛时样本数为零，不会用历史回放或合成测试填充。

## 运行检查

本地和云端测试验证真实模型能输出影子排名、正式结果不变、缺资料和坏模型不中断正式预测、赛后指标正确、晚到数据被排除，以及一场多版本去重。公开采集检查工作流增加影子模型和结算测试，仍不会运行或改写任何真实比赛预测。

紧急停止影子测试可在预测执行环境设置 `KEIBA_WORKOUT_SHADOW_MODE=off`；默认 `shadow`。没有通过此变量切换正式排名的模式。

## 地方流程隔离

地方比赛在预测入口直接跳过训练采集，不导入新增采集或影子模块；只有带有对应影子记录的审计才尝试加载新增结算组件。新增组件导入或执行失败时记录错误，正式预测和赛果仍保存。比赛编号的场地段也参与判断，避免缺少来源标签时误入中央流程。

`tests/test_local_pipeline_isolation.py` 故意阻断新增模块，验证地方出马表、近走、原模型预测、早期及最终回传和赛果保存。`.github/workflows/local-prediction-check.yml` 提供一次性云端检查：运行隔离及调度测试，读取两天地方列表，只抽查一张出马表和一匹马的近走，不创建实际预测任务。
