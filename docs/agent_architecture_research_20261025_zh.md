# Agent算法架构研究（2026-10-25）

## 结论

**仍有改进空间，本轮最值得继续的是中央草地的“连续历史特征 + 直接前三目标排序”，不是继续微调几个整数分，也不是立即把整个系统推倒。** 它在全部630场合格草地样本的三次日期分折中都提高了覆盖席位；但统计区间仍包含零，与当前线上固定模型的比较也存在指标取舍，尚不构成直接替换生产模型的证据。

中央泥地的复杂树模型没有同步受益。较简单的正则化线性模型有正向信号，但全历史重复分折和扩展时间验证方向不一致。本轮不修改草地、泥地、地方的生产模型、界面或用户自定义预测。

本轮新增了可复现的离线架构实验和8项特征测试，连同既有相关实验测试共30项通过；所有实验完成，生产文件哈希未变化。不是仅给出方案或训练集上的拟合成绩。

## 验证前固定的研究协议

目标仍为预测前五覆盖实际前三的席位数、三匹全覆盖及至少两匹；冠军相关指标作为保护项。沿用此前中央优先范围，中央草地和泥地分别训练，地方本轮不调参。完整原始数据、旧快照、线上模型均保留。

依据当前代码的研究问题：

- 草地最终名次混合冠军模型、前三模型及原始排名，且保留首选，目标并不完全等价于前三席位覆盖。
- 原始表现经过离散桶、整数评分和多层加减分后才进入学习模型，连续信息可能损失。
- 当前草地特征主要是比赛内标准化分项，部分绝对条件消失；泥地虽增加条件字段，仍沿用较多压缩分项。
- 原始输入没有完整比赛用时、年龄、性别、体重等字段，不能把完整审计等同于完整赛前信息。
- 正常路径先排好名次，再调用LLM做解释；修改解释提示词本身不会改变所选五匹。

如果各马的前三边际概率可信，选择概率最高的五匹即可最大化预期覆盖席位，因为预期覆盖等于所选五匹前三概率之和，不要求马匹结果相互独立。但“三匹全部覆盖”涉及联合结果，不能由边际概率之和直接保证。本轮同时保留这两个指标，避免偷换目标。

固定候选如下，不做参数网格搜索，不在看到结果后挑选组合：

| 候选 | 研究问题 |
|---|---|
| `policy_direct` | 使用同一前三模型分数直接排序，取消混合、首选保护及泥地小头数门槛，检验最终选择政策 |
| `equal_place` | 当前特征、等出走马训练权重、直接前三排序；泥地与上一组相同，仅计一次比较 |
| `rich_hybrid` | 新增连续历史及绝对/相对条件，保留当前混合和启用政策，单独测试信息表达 |
| `rich_direct` | 新特征加当前分项，等权训练，直接排序 |
| `raw_direct` | 仅连续历史与比赛条件，移除手工分项，测试替代评分主干 |
| `rich_ranker` | 使用丰富特征做比赛内排序学习，前三标签同为1，其余为0 |
| `rich_linear` | 使用丰富特征和正则化逻辑回归，检验较简单学习器的泛化能力 |

连续特征只使用目标日之前冻结输入：最近三走、最近八走、同草泥、同赛场近距离、近365天的名次比例、着差、位置变化、末三段、显式赛级，以及休养、距离变化、负重、枠位、本场头数等。保留绝对值并添加同场相对值；未知保留缺失，不预先奖励或处罚。按比赛ID去重，无ID时用日期/赛场/距离去重。赔率、人气、马名、马ID不进入模型。

树分类器沿用生产超参数；排序树固定180轮、7叶、学习率0.06、最小叶样本40、L2为2；线性模型固定C=0.1。排序树使用成熟的LightGBM实现，优化的是排序代理损失，并非精确覆盖席位损失，最终以实际覆盖评价。参考：[排序器文档](https://lightgbm.readthedocs.io/en/v4.6.0/pythonapi/lightgbm.LGBMRanker.html)、[排序参数文档](https://lightgbm.readthedocs.io/en/v4.6.0/Parameters.html#lambdarank_truncation_level)。

全部合格已结算完整样本做日期分组五折，重复种子42、137、2026。每折重新拟合全部模型和线性预处理；同日不跨训练/测试。再作五日期块扩展时间验证，并以10月22日为固定截止训练，单列后续数据。小样本切片不作为独立上线门槛。对草地7项、泥地6项共13项主要比较做日期聚类和多重比较检查。

## 为什么尚未大幅提升

### 1. 换对与换错大量抵消

草地重点候选三轮合计改变1,366场次的Top5集合（含同一比赛三次重复），新选入的马中有514个前三席位，同时失去444个原本已覆盖席位，净增加70，折算每轮+23.33。全替换手工评分则补回604、失去548，反而净增更少。

所以不是模型完全找不到漏选马，而是**还不能足够准确地判断，找回谁时不该挤掉谁**。只挑成功救回的案例，会严重夸大收益。

### 2. 总比赛数不等于每个子模型的信息量

虽然已有7,093场预测，合格中央重算样本仅草地630、泥地496，且分别只有41、38个比赛日。单场马匹的结果相关，三个重复分折也不是三个独立数据集。数百个条件特征和更多模型很容易消耗这点有效信息。

草地8,324个出走观察中，1,329个没有有效历史，占15.97%；2,758个最多只有两场历史，占33.13%；全场无历史107/630，占16.98%。泥地相应为571/6,799、1,571/6,799、37/496。无历史时继续调近期趋势、距离往绩系数，不能凭空创造可区分信息。

### 3. 当前输入缺的是能力判断所需的语义，不只是更多行

[输入结构](D:/keiba/new/keiba_llm_agent/schemas/race_data.py:9)没有完整比赛用时、年龄、性别、马体重及其变化、历史负重等字段；正式赛级也没有独立字段。根据比赛名称仍无法明确识别本场赛级的有草地199/630、泥地108/496，不能把猜测当确定标签。

已有名次、着差、末三段、转弯位置很有价值，但尚不能充分区分“慢节奏中轻松跑出第六”和“强对手快速比赛中接近前三”。在相同信息上更换分类器、排序器和分数权重，仍可能反复交换相似的错误。

### 4. 只修第六名边界也不够

现架构折外漏掉的实际前三马中，草地45.96%、泥地47.44%原本排在第九名或更后。只在第五、六名之间交换，无法覆盖这部分深排漏选。需要对全体出走马评价证据，而不是只让LLM复述已经选出的五匹。

### 5. 概率改善和选马改善不是一回事

现草地分类器在折外的平均输出为43.62%，实际每个出走观察进入前三的比例为22.71%；加权训练信号不能直接解释为真实前三概率。等权丰富特征候选平均22.55%，布里尔误差从0.2085降到0.1524，但平均接近真实频率仍不证明逐个概率已经校准。

这些是**前三分类器组件**，不是最终混合排名、网页自信度或投注概率的准确性评估。单调校准通常不改变同场排序，不能把概率数字调漂亮当命中率提升。

正常路径在[确定性预测构建](D:/keiba/new/keiba_llm_agent/agents/race_analysis_agent.py:153)之后才调用展开和[LLM解释增强](D:/keiba/new/keiba_llm_agent/agents/race_analysis_agent.py:174)。只改这部分提示词不会改变最终所选五匹。

## 下一步优先顺序

1. **草地先收敛到一个主要候选。** 以本轮`rich_direct`为下一代候选，现手工分项降为输入之一，不再让冠军混合决定覆盖目标；保留当前部署模型作对照。暂不叠加新的小样本阈值或自动替换线上文件。核心验证仍覆盖全部合格full，并单列时间外、换对/换错和三个覆盖指标。
2. **优先补有信息增量的字段。** 首批是正式赛级及来源、完整用时和分段、历史负重、年龄/性别/体重变化、出走/取消状态、采集成功与真正无历史的区别、准确采集及开跑时间。旧记录保留；不可恢复的字段标未知，不用现在的信息回填成当时已知。
3. **在新字段可用后建立条件校正能力与对手强度。** 速度须校正场地、距离、状态及节奏；对手关系按当时已知比赛构建，不能使用目标赛后的表现。现直接交锋与历史名次仍可保留，但不要仅因参加过高级别就推定实力。收益需逐项独立实验，本轮没有验证这些尚不存在的字段。
4. **单独处理历史稀少状态。** 优先明确新马、有效历史少与抓取失败的区别；再研究可靠的训练/调教、血统后代统计等先验。是否能取得、是否赛前可用、是否改善覆盖，需先验证，不能凭描述加分。
5. **泥地保留当前模型，线性候选继续独立研究；地方本轮不动。** 不能因为草地见到正向信号就同步修改所有赛种，更不能用冠军命中或自信度提升替代Top5的前三覆盖目标。

这些方向有不同证据等级：第一项已有本轮折外正向信号；第二项是已确认的数据表达缺口；第三、四项是待验证的建模假设，**没有本轮实测的命中率提升数字**。
