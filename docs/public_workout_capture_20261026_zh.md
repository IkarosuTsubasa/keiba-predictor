# 公开训练资料自动采集

2026-10-26 起的代码接入说明。此次只启用资料采集，不变更正式模型、排序、权重或网站文案；回测增益不代表采集开启后会自动出现在正式预测中。

## 采集范围

- 中央草地、中央泥地：预测前读取该场 netkeiba 公开训练页面，保存 A/B/C/D 评级和训练短评。
- 地方、障碍、无出马表或无有效中央比赛编号：跳过，并在审计中记录原因。
- 不使用会员登录、密码、Cookie 或 VPN，不获取付费分段训练时间。
- 比赛编号、马番和马匹 ID 必须对应。页面身份或马匹对应错误时，不提供可用评级。缺失评级保持缺失，不当作低评级。

## 执行和失败处理

`predict-race` 和非 dry-run 的 `analyze-url` 自动执行。Render 与 GitHub Actions 共用此入口；直接离线 `run_analysis` 和回测不会联网补抓。

每次采集最多一次请求，无重试、无重定向；连接超时 3 秒、读取超时 6 秒，并限制响应大小和读取总时长。同一运行环境、同一比赛及名单在 10 分钟内复用最近记录，失败记录也参与限频。不同临时 GitHub runner 之间不共享缓存。收到访问限制、超时或页面未发布时保留状态，原预测继续。

默认开启。紧急关闭可在执行预测的环境设置 `KEIBA_CAPTURE_PUBLIC_WORKOUTS=0`；GitHub Actions 如需关闭，应给预测步骤设置此变量。该开关不影响当前正式打分。

另有仅手动触发的 `.github/workflows/public-workout-check.yml`，供 GitHub runner 实际连通性检查：只读一张出马表和一张训练页，不运行预测、不回调网站、不改历史数据。结果及原始证据保存在该次工作流附件中。

## 原始证据和保存

- 本地追加保存到 `keiba_llm_agent/data/workout_observations/<race_id>/<时间戳>_<唯一标识>.json.gz`，不覆盖历史记录。
- 同一记录也嵌入完整审计包的 `inputs.supplementary_observations.public_workout`。原始响应按 gzip + base64 保存，附原始字节 SHA-256、来源地址、请求及接收时间、状态和解析结果。
- GitHub Actions 沿用现有回调传输完整审计包，Render 保存到现有 `agent_backtest_audit` 及预测版本目录。独立采集文件也列入工作流诊断附件，即使后续预测失败仍可检查。
- 原始网页只作证据；新增字段不进入 RaceData、LLM 提示或打分器。赔率和人气不从此页提取为特征。
- 页面实际发布时间未知时留空。仅在有含时区的开赛时间时判断是否赛前收到；赛后抓取标记为非赛前，无法判断则为空。缓存复用保留首次接收时间。
- 本次不新增清理逻辑，不删除或迁移现有预测、赛果、审计或 Render 快照。

## 验证

新增采集与集成测试 8 项，原 URL 入口测试 7 项、预测流程测试 5 项、审计测试 2 项通过。覆盖身份校验、缺失评级、访问限制、超时、响应大小、限频、追加存储、原始字节校验、泥地/地方范围，以及 GitHub 回调格式和赛果回填后的证据保留。

离线核对已保存的 630 场公开训练页面：8,324 匹马、8,283 条有效评级，与研究采集结果逐匹一致；595 场完整、35 场部分缺失。正式草地模型的文件及特征源码校验通过。部署后的网络抽查只用于验证采集连通性，不算新的赛前预测样本或命中率提升证据。

后续用真正赛前冻结的资料评估 Top5 对实际前三名覆盖，分别检查新马、有历史马、大型比赛和多头比赛，再决定新增评级如何进入正式排序。
