# Project Context: Keiba Predictor

## What This Project Is

A **JRA horse racing prediction system** deployed as a web service on **Render**. The site publishes predictions generated by multiple LLM-based predictors, surfaced through a frontend UI.

## Architecture Overview

### Data Pipeline (how training data is sourced)
Race data is collected via **web scraping** (Selenium + BeautifulSoup):
- `race_card.py` — scrapes upcoming race card info
- `new_history.py` — scrapes historical race results
- `odds_extract.py` — scrapes live odds

Orchestrated by `pipeline/run_pipeline.py`.

### Prediction Models (v1–v5)
Five quantized predictor models, each with a different LLM backend:

| File | Version | Backend |
|------|---------|---------|
| `predictor.py` | v1 | baseline (LightGBM + rule-based) |
| `predictor_v2_opus.py` | v2 | Claude Opus |
| `predictor_v3_premium.py` | v3 | premium LLM (Claude) |
| `predictor_v4_gemini.py` | v4 | Google Gemini |
| `predictor_v5_omc.py` | v5 | OMC orchestrated |

### Published Predictions (4 LLMs on the website)
The website (`frontend/`) displays predictions from **4 LLM outputs**:
- `predictions.csv` (v1 baseline)
- `predictions_v2_opus.csv`
- `predictions_v3_premium.csv`
- `predictions_v4_gemini.csv`

### Deployment
- **Backend/API**: FastAPI via `pipeline/web_server.py`
- **Hosting**: Render (see `render.yaml`)
- **Frontend**: `frontend/` directory

## Key Directories
- `pipeline/` — orchestration, configs, web server, logs
- `frontend/` — web UI served on Render
- `pipeline/data/<scope>/` — per-scope logs and race snapshots

## Scopes
Predictions are scoped by race surface: `central_dirt`, `central_turf`, `local`
